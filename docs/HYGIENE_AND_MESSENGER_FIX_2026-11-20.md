# Аудит после релиза r45: кнопки заказа, `theme-color`, мёртвый CSS

Дата: 2026-11-20. База: merge-коммит PR #176 (`ac97377`). Ветка:
`arena/1ecb7505-milovi-cake`.

Аудит проводился только по исходникам и живой разметке (без браузера в среде):
33 HTML-страницы, 1877 `href`/`src`, CSS/JS-бандлы, sitemap, артефакт Pages,
наборы тестов. Ниже — что нашлось, что исправлено и что сознательно не
трогалось.

## 1. Настоящий дефект: тупиковые кнопки заказа в пригородах

В `prigorody/_template.html` кнопки калькулятора жили с заглушкой:

```html
<a id="btnWA" href="#" target="_blank" … onclick="buildWA(event)">
<a id="btnTG" href="#" target="_blank" … onclick="buildTG(event)">
```

Работа держалась на `onclick`, а адрес был пустым. На главной в тот же момент
стояли настоящие адреса. Последствия на 15 файлах (шаблон + 14 собранных
пригородов):

* если `buildWA`/`buildTG` не отработали (ошибка скрипта, отключённый JS,
  блокировщик) — клик открывал в новой вкладке пустую копию страницы, заказ
  терялся без ошибки в консоли;
* Ctrl/средний клик давал тот же дубль страницы вместо чата;
* краулеры и превью ссылок не видели адреса мессенджера.

Исправлено: `href="https://wa.me/79119038886"` и `href="https://t.me/MiloviCake"`
— ровно те адреса, которые открывают `buildWA()`/`buildTG()`. Атрибуты
приведены к порядку `href → target → rel → class → onclick`.
На главной `#btnTG` вёл на `t.me/+79119038886`, хотя JS открывает
`t.me/MiloviCake`; фолбэк выровнен с фактическим поведением.
14 пригородов пересобраны `prigorody/build.py`.

## 2. Новый контракт против повторения

`tests/test_messenger_contract.py` (статический, без сети, входит в
`npm run audit:content-contracts`):

1. ни на одной странице нет `href="#"`;
2. у `#btnWA` / `#btnTG` `href` совпадает с адресом, который открывает
   `js/main.js`, сохранены `target="_blank"` и `rel` с `noopener`;
3. главная и все пригороды отправляют заказ по одинаковым адресам.

Проверено мутацией: подмена `href` в одном пригороде на `#` роняет все три
теста, после пересборки они снова зелёные.

## 4. Мёртвый CSS: −5,0 КБ в трёх файлах

Удалены правила, чьи классы не встречаются ни в разметке, ни в генераторах, ни
в JS (включая строки, которые собираются в `prigorody/build.py`):

| Файл | Правил | Байт |
|------|--------|------|
| `css/style.css` | 29 | 3 832 |
| `css/v20-dark-and-fixes.css` | 7 | 824 |
| `css/mc-2026.css` (остатки прежнего переключателя темы: `.mm-theme-row`, `.mm-theme-icons`) | 5 | 393 |
| **итого** | **41** | **5 049** |

Правила выбирались консервативно: удалялось только то, где **каждый** селектор
из списка содержит класс, отсутствующий во всём коде, при этом ни один префикс
класса не встречается отдельно (иначе класс мог бы собираться конкатенацией).
Селекторы с элементом/`id` (например `[data-theme="dark"] select`) не
затрагивались. После удаления: скобки сбалансированы (1968/1968), `!important`
в `mc-2026.css` по-прежнему 190, `tinycss2` не показывает новых ошибок разбора.

## 7. Что проверил и признал ложными срабатываниями

Чтобы это не искали заново:

* **Дубль `<link rel="stylesheet" href="fonts-italic.css">`** на 19 страницах —
  это осознанный async-паттерн: `media="print" onload="this.media='all'"`
  плюс `<noscript>`-фолбэк. При включённом JS запрос ровно один, дубля нет.
* **54 `<img width≥700>` без `srcset`** — все внутри `<picture>` с
  `<source type="image/avif" media=…>`; адаптивность уже есть.
* **«Неиспользуемые» функции в `js/main.js`** (`initTheme`, `initCalcRows`,
  `initMobileCalcDock`, `applyInitialOrbs`, …) — это именованные IIFE, они
  выполняются сразу. Реально мёртвая нашлась одна: `getStageCenter()`.
* **`.map-review*`, `.wed-proof-video-frame`** — классы, которые собирает
  `prigorody/build.py` и которые ищут тесты; при удалении CSS их учитывали,
  поэтому в мёртвые они не попали.
* **Закрытое меню** — `visibility: hidden` + `pointer-events: none`, поэтому
  его ссылки не попадают в Tab-порядок; `inert` не нужен.
* **`tinycss2`** сообщает одну ошибку разбора в `css/style.css` — она была и
  до правок, скобки и структура файла в порядке (проверено отдельным счётом
  с вырезанными комментариями и строками).

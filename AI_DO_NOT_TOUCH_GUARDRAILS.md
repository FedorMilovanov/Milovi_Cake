## 1. Главная — WhatsApp / Telegram / MAX

ЭТО НЕ ТРОГАТЬ без прямого письменного указания владельца.

На главной странице hero-мессенджеры должны оставаться именно такими:

- цвета строго брендовые:
  - WhatsApp — зелёный `#25D366`
  - Telegram — голубой `#229ED9`
  - MAX — фиолетовый `#7B5EE8` / `#8e74ee`

**Запрещено:**
- перекрашивать эти иконки в белый
- заменять их на обычные pill-кнопки с текстом
- удалять SVG `textPath` / кольцевой текст
- удалять hover-анимацию «название вверх»
- удалять классы `messenger-group--ring`, `btn-hero-ring`, `.hero-ring-text`, `.hero-flat-text`
- переписывать R9/R10 protected CSS-блок в `css/premium-overrides.css`

## 5. R15 — защищённые визуальные решения

- В блоке `#contacts` SVG-трубка телефона должна быть чисто чёрной с мягкой светлой/gold подсветкой. Запрещено возвращать белую трубку или случайную заливку.
- В футере ссылки телефона / WhatsApp / Telegram должны быть нейтральными premium chips. Запрещено делать их яркими, случайно окрашенными или визуально похожими на баг.
- Анимация hero-мессенджеров должна поддерживать оба варианта SVG-разметки: class-based главной (`.hero-ring-text`, `.hero-flat-text`) и id-based пригородов (`ring-text-*`, `flat-text-*`). Не удалять R15 fallback в `js/main.js`.
- Описательные subtitle-тексты должны оставаться мягкими, менее квадратными: `Cormorant Garamond`, `font-style: normal`, без курсива. Не возвращать грубую квадратную sans-подачу без согласования.

## 6. R18 — защищённая корзина (КРИТИЧНО)

В `js/main.js`:
- `buildCartKey(numId, mode, hasMaxi, fillName, decorName)` — единая точка формирования ключа корзины
- `parseCartKey(key)` — обратная совместимость
- `addToCart()` использует `buildCartKey()` для всех товаров

**Запрещено:**
- «упрощать» в формат `id` для товаров без `hasMaxi` — это сломает bento-режимы
- Менять формат ключа без обновления `parseCartKey()`
- Использовать прямую конкатенацию (`id + ':' + fill`) — только через `buildCartKey()`

## 7. R18 — Theme Toggle SVG (КРИТИЧНО)

В HTML иконки имеют классы:
- `.theme-icon--moon` — луна
- `.theme-icon--sun` — солнце

CSS управляет только `display: block/none` в зависимости от `data-theme` атрибута на `<html>`.

**Запрещено:**
- Возвращать старые классы `.sun-icon` / `.moon-icon` (они конфликтовали)
- Управлять видимостью через `position:absolute` и `opacity` (это вызывало мигание)

### 7.1 Тема по умолчанию (R11)

- Весь сайт — **светлая** тема по умолчанию, **КРОМЕ `meringue-roll/`** — она **ТЁМНАЯ ПО УМОЛЧАНИЮ**.
- На meringue anti-FOUC inline-скрипт ставит `data-theme="dark"`, если нет явного выбора пользователя; если `localStorage.mc_theme === 'light'` — уважается светлая. Inline `<style id="anti-fouc">` там инвертирован (фон по умолчанию `#1a1108`).
- **Запрещено** возвращать meringue к светлому дефолту.
- Переключатель темы должен быть доступен на **всех** страницах (десктоп — шапка; лендинги — `.lp-theme-toggle` перед `</header>`; главная/пригороды — `.mm-theme-row` в мобильном меню).

## 8. Перед деплоем — обязательные проверки

```bash
npm run qa
npm run build:pages
npm run audit:pages
```

`npm run qa` включает статические аудиты и все браузерные тесты Playwright; перед его запуском должны быть установлены зависимости проекта и Chromium для Playwright. В CI для сборки и проверки кандидата задаётся один и тот же `RELEASE_SHA`. Локальный `_site/` генерируется заново и не должен попадать в Git.

При изменении любого версионируемого CSS/JS ассета — **поднять cache-bust версию** `?v=` синхронно во всех HTML-потребителях и в `sw.js` (`PRECACHE` + `CACHE_NAME`), а при изменении `prigorody/_template.html` или `prigorody/_cities.csv` запустить:
```bash
python3 prigorody/build.py
python3 scripts/sync_prigorody_sitemap.py
```

## 10. SEO / Schema.org / GEO Guardrails (проверяются `scripts/audit.py`)

- **Единый граф сущностей**:
  - `LocalBusiness` (`https://milovicake.ru/#business`): индекс строго `196158` (Пулковская ул., 19), координаты строго `59.83494, 30.350265`, непустые поля `image` и `hasMap`. У главного бизнес-узла `image` может быть списком, а ссылка на карту ведёт на соответствующую карточку кондитерской.
  - `Person` (`https://milovicake.ru/#viktoria`): не отождествлять адрес кондитерской с личным адресом и не требовать `taxID` в разметке. Связь профиля с бизнесом на главной проверяется контрактом.
  - `Product`: проверяются `"brand"`, `"image"` и `"description"`, включая продукты внутри `ItemList`. `priceValidUntil` необязателен и допустим только для подтверждённой даты окончания цены.
- **Паритет `FAQPage`**: вопросы и ответы JSON-LD должны соответствовать видимым FAQ-компонентам страницы. `scripts/faq_contract.py` проверяет оба направления, а не простое наличие вопроса в произвольном тексте.
- **Граница с `french.milovicake.ru`**: *Patisserie Russe / Milovi School* (`https://french.milovicake.ru/`) — отдельная образовательная библиотека, поддерживаемая Milovi Cake. Запрещено выдавать её материалы за меню кондитерской или утверждать, что `milovicake.ru` печёт на заказ десерты по рецептам библиотеки.
- **Даты `sitemap.xml`**: `<lastmod>` отражает фактическое существенное изменение страницы, должен быть корректной и не будущей датой. Для пригородов обновлять дату в `_cities.csv` и синхронизировать карту; браузерный тест не закрепляет исторические даты. Дата в миграционном fallback `scripts/analytics_contract.py` используется только при добавлении отсутствующей записи `/privacy/`.
